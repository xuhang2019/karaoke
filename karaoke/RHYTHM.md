# 逐字节奏练习

把原项目最终 `cues.json` 中每个 `unit` 的 `start` / `end` 直接显示成色块：

- 色块宽度 = `(end - start) × 每秒像素数`，位置 = `(start - 本句起点) × 每秒像素数`。
- 停顿保留为空白；相邻字不会因排版被等分。上游合并的词组保持一个色块，估算时间明确提示。
- 一次练一句，下面预读下一句；播放完自动停下，可重练、循环或手动换句。
- 跟着原唱按住空格，每个字结束时松开。也可以用鼠标、触屏或触控板长按下方按钮。
- 青绿色条记录实际按压，与原唱共用时间轴；句末显示时长、起点偏差、漏按和多按。

## 直接打开练习网页

[打开逐字节奏练习](https://aiden-lyric-rhythm.intactray2.chatgpt.site/)（使用创建者的 ChatGPT 账号登录）。
点击「试用节奏示例」即可练习，也可以导入本地音频和已有 `cues.json`。
线上版不运行神经网络；自动处理歌曲使用下面的本地原项目服务。

## 在原项目中使用

按原有 [SETUP](../SETUP.md) 启动服务，在顶部点击「节奏练习」，或打开
`http://127.0.0.1:8746/assets/rhythm.html`。从下拉框选择准备完成的歌曲。
训练页读取已有的字幕、伴奏和主唱成品，不重新跑模型、不改字幕或音轨。
歌曲在原点歌台处理完成后，点击「刷新曲库」即可读取。

训练页在同一个 AudioContext 上调度全部原唱音轨，按句截取播放，不需要视频。
为了反复定位，它目前会把选中歌曲的音轨完整解码到浏览器内存；长音频占用更多内存。
不要同时在另一个 KTV 标签页播放。多个训练页之间会主动停止旧页面的声音。

## 不安装模型，先试手感（Mac / Linux）

```sh
git clone https://github.com/xuhang2019/karaoke.git
cd karaoke
python3 -m http.server 8765 --bind 127.0.0.1 --directory karaoke/web
```

在浏览器打开 `http://127.0.0.1:8765/rhythm.html`，点击「试用节奏示例」→「播放这一句」。
示例是自写短句与合成提示音，展示短音、长音、停顿和连续音，**不是模型对齐准确率测试**。
在终端按 Ctrl+C 停止服务器。前端没有构建步骤或额外模型依赖。

也可展开「导入本地音频和时间轴」，选择同一录音的 MP3 / WAV 和最终 `cues.json`。
文件只在当前浏览器内读取，不上传。只有 MP3 或普通逐行 LRC 不足以恢复逐字时长；
须先由上游神经网络流程生成逐字结果。没有 `units` 的时间轴会明确报错，不编造时间。

Apple Silicon 的神经网络处理沿用上游 MPS 路径，CPU 路径也保留；本次只修改展示层。
本次验证环境是 Linux / Chromium，尚未在真实 Mac / Safari 或触屏设备上实测。

## 操作

| 操作 | 功能 |
| --- | --- |
| 播放这一句 / Enter | 从本句前一秒开始重练，清空本轮记录 |
| 空格按下 / 松开 | 记录一个字的起点 / 终点；自动重复 keydown 不重复计数 |
| 长按下方按钮 | 鼠标、触控板或触屏的同等操作 |
| ← / → | 上一句 / 下一句 |
| 循环本句 | 结束后保留 1.2 秒查看反馈，再重播 |
| 适应整句 | 按当前宽度等比例缩放时间轴，完整显示一句 |
| 固定 px / 秒 | 跨句保持固定时间尺度，过长时横向滚动 |

换句、换歌、切换缩放、窗口失焦、后台隐藏或音频中断时停止当前练习，避免卡住的长按。
重新调整窗口尺寸会停止并重新排版当前句。播放结束保留反馈，点击播放可重试。

## 反馈含义与边界

以时间顺序做一对一按压匹配（起点容差 250 ms），一次长按不会同时算作两个字。
起点偏差为负表示提前、为正表示滞后；长短偏差为正表示按得太长。
结果只是你与当前时间轴的差异，不代表模型时间轴已通过人工验证，也不是歌唱评分。
蓝牙、键盘和音频设备延迟仍会影响感觉；浏览器已报告的输出延迟用于显示和按压时钟补偿。

保留上游尾音重叠，不把前一个字截短。多个演唱声部重叠时，一根手指不能完整表达所有声部；
可先观察色块，不应把此类材料的漏按反馈视作真实能力不足。
